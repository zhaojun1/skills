# Stock Screener（价值投资筛选入池）

从 A股或港股中筛选出值得进一步深度研究的股票，进入投资股票池。本技能解决"从0到1"的发现环节——不是告诉你买什么，而是帮你缩小研究范围。

### 快速索引

| 场景 | 直接跳到 |
|------|---------|
| 用户说"帮我筛选XX行业" | 从头执行 Phase 1→5 |
| 用户已给了候选股票清单 | Phase 1 → 跳过2/3 → Phase 4 |
| 不确定投资偏好 | Phase 1 默认"长期复利" |
| 想了解筛选条件怎么定的 | [screening-criteria.md](references/screening-criteria.md) |
| 想了解输出格式 | [pool-output-template.md](references/pool-output-template.md) |
| 执行中遇到了异常 | [失败模式处理](#失败模式处理) |

## 核心约束

**AI 无法遍历全市场5000+只股票**，因此筛选必须是人机协作：
- 用户提供**行业范围或候选方向**（如"白酒行业""港股互联网""消费龙头"）
- AI 负责用价值投资框架**生成量化条件 + 逐只定性过滤**
- 最终产出的是"待深研股票池"，而非"买入清单"

## 反例黑名单（不能做的事）

| # | 反模式 | 为什么不行 |
|---|--------|-----------|
| 1 | **把筛选结果当买入建议** | 筛选是发现不是决策，入池 ≠ 买入 |
| 2 | **编造财务数据** | 无法确认的数据必须标「待验证」，不编造 |
| 3 | **跳过 Phase 1 信息确认** | 不知道市场/行业/偏好就筛选等于盲选 |
| 4 | **凭记忆罗列候选** | 必须基于实际搜索结果构建，不靠模型记忆 |
| 5 | **对不确定生意假装「看得懂」** | 看不懂就老实说看不懂，不懂不碰是铁律 |
| 6 | **跳过 CHECKPOINT 直接出结果** | 每个 Phase 结束都有 🛑 STOP，必须先暂停 |
| 7 | **用单一框架排除全部公司** | 条件太严可能漏掉好公司，条件通过的只说明「可以看」 |
| 8 | **不标注数据来源** | 每个数据点必须标注来自 Wind/同花顺/年报/搜索结果 |

## 你的工作方式

采用顺序流程，五步递进：

```
Phase 1: 筛选策略确认 ← 理解用户要找什么
    🔴 CHECKPOINT · 🛑 STOP → 用户确认后再进入 Phase 2
Phase 2: 量化条件生成 ← 从大师框架提取可量化指标
    🔴 CHECKPOINT · 🛑 STOP → 用户确认条件后再进入 Phase 3
Phase 3: 候选清单构建 ← 人机协作产出10-20只候选
    🔴 CHECKPOINT · 🛑 STOP → 用户确认候选后再进入 Phase 4
Phase 4: 逐只快速检验 ← 用L1+L2逻辑过滤
Phase 5: 输出股票池清单 ← 含核心看点+风险+下一步
```

## Phase 1：筛选策略确认

开始前必须向用户确认以下信息，缺一不可：

### 必问项

| 项目 | 说明 | 示例 |
|------|------|------|
| **目标市场** | A股 / 港股 / 两者皆可 | "A股" |
| **行业或方向** | 具体行业、赛道或投资主题 | "白酒""消费""港股互联网" |
| **投资偏好** | 长期复利 / 周期反转 / 高股息 | 默认：长期复利 |

### 可选项（用户不回答则使用默认值）

| 项目 | 默认值 |
|------|--------|
| 市值范围 | 不限（但优先中大市值） |
| 是否已有候选清单 | 无 |
| 特别排除的行业 | 无 |
| 偏好的筛选框架 | 综合使用（老唐+巴菲特+段永平） |

**关键判断**：如果用户直接提供了候选清单（如"帮我看看这10只股票哪些值得研究"），跳过 Phase 2-3，直接进入 Phase 4。

### 🔴 CHECKPOINT · 🛑 STOP

Phase 1 完成后，**必须暂停**等待用户确认：
- 目标市场、行业/方向、投资偏好三项确认无误
- 用户确认后再进入 Phase 2
- 若用户提供候选清单，确认后直接跳转 Phase 4

## Phase 2：量化条件生成

根据用户偏好，从价值投资大师框架中提取可量化的硬指标，形成筛选条件。

> 详细的筛选条件库，读取 `references/screening-criteria.md`

### 标准条件集（长期复利偏好）

从三大框架提取的核心量化指标：

**来自老唐三大前提（硬门槛）**：

| 指标 | 阈值 | 理由 |
|------|------|------|
| 经营现金流/净利润 | ≥ 80%（近3年均值） | 利润为真 |
| ROE | ≥ 15%（近3年均值） | 利润可持续+资本效率 |
| 资本支出/净利润 | ≤ 50%（近3年均值） | 维持盈利无需大量资本 |

**来自巴菲特十二准则（加分项）**：

| 指标 | 阈值 | 理由 |
|------|------|------|
| 毛利率 | ≥ 40% | 定价权+护城河体现 |
| 净利率 | ≥ 15% | 商业模式质量 |
| 负债率 | ≤ 50%（非金融） | 财务安全 |
| 营收增速 | ≥ 8%（近3年CAGR） | 成长性 |

**来自段永平不为清单（排除项）**：

| 排除条件 | 理由 |
|---------|------|
| 看不懂的生意（复杂金融、激进多元化） | 不懂不碰 |
| 依赖单一政策补贴 | 利润不真实 |
| 频繁变更会计政策 | 诚信风险 |

### 条件调整

根据用户偏好调整条件严格度：
- **高股息偏好**：增加股息率 ≥ 3%、派息比率 ≥ 50% 的条件，放宽营收增速要求
- **周期反转偏好**：放宽 ROE 和利润增速的当期要求，改看周期中枢盈利能力
- **保守风格**：所有阈值收紧（如 ROE ≥ 20%、负债率 ≤ 30%）

将最终筛选条件清单展示给用户确认。

### 🔴 CHECKPOINT · 🛑 STOP

Phase 2 完成后，**必须暂停**等待用户确认：
- 展示生成的量化条件清单（含阈值+理由）
- 用户可要求放宽/收紧特定条件
- 用户确认后再进入 Phase 3

## Phase 3：候选清单构建

这是人机协作的核心环节——AI 无法查数据库，需要通过搜索和知识来构建候选清单。

### 3.1 信息收集策略

按优先级搜索候选公司，每步给出具体工具调用：

**Step 1：知识库搜索**

```
search(source="kb", query="{行业} 上市公司 护城河 财务分析")
search(source="kb", query="{行业} 龙头 ROE 毛利率")
```

→ 若知识库无相关记录，直接跳到 Step 2。

**Step 2：互联网搜索**

```
web_search(query="{行业} A股上市公司 龙头企业 列表")
web_search(query="{行业}股票 ROE排名 前20")
web_search(query="{行业}赛道 投资标的 分析")
web_search(query="{行业} 毛利率 净利率 对比")
```

→ 搜索关键词按实际行业填充（如"{行业}" → "白酒"）。

**Step 3：行业分类切入**

按申万/恒生行业分类，逐个子行业识别头部公司：
- A股 → 申万二级/三级行业分类
- 港股 → 恒生行业分类
- 每个子行业取营收/市值前3-5名

### 3.2 初步筛选

对搜索到的公司，用 Phase 2 的量化条件做**纸面快速过滤**：

**数据获取步骤**（每只候选逐个执行）：

```
# 对每只候选公司，搜索获取以下数据：
web_search(query="{公司名称} ROE 近3年 2023 2024 2025")
web_search(query="{公司名称} 毛利率 净利率 经营现金流 资本支出")
web_search(query="{公司名称} {股票代码} 财务指标 营收增速")
```

- 将数据填入候选清单表格，标注来源（Wind/同花顺/年报/搜索结果）
- 不满足硬门槛的直接排除，不进入候选清单
- 记录每只候选股的"通过条件"和"待确认项"
- 数据不可获取的指标标注「待验证」——不编造

### 3.3 产出候选清单

输出 10-20 只初步通过量化条件的候选股，格式：

```markdown
## 候选清单（[行业] [市场]）

| # | 公司名称 | 代码 | ROE | 毛利率 | 现金流/利润 | 资本支出/利润 | 通过条件 | 待确认 |
|---|---------|------|-----|--------|------------|-------------|---------|--------|
| 1 | XX公司 | 600XXX | 25% | 60% | 110% | 20% | 全部通过 | — |
| 2 | YY公司 | 000XXX | 18% | 45% | 85% | 35% | 基本通过 | 毛利率趋势 |
```

**确认门**：将候选清单展示给用户，请用户：
- 确认是否要增删候选
- 指定哪些优先检验
- 确认后进入 Phase 4

### 🔴 CHECKPOINT · 🛑 STOP

Phase 3 完成后，**必须暂停**等待用户确认：
- 展示候选清单（含量化条件通过情况 + 待确认项）
- 用户增删候选后，标记优先检验顺序
- 用户确认后进入 Phase 4

## Phase 4：逐只快速检验

对候选清单中的每只股票，执行 `stock-deep-dive` 的 Layer 1 + Layer 2 逻辑进行快速定性过滤。

### 检验流程（每只候选股）

**Step 1：三大前提快检**（老唐框架）

| 检验项 | 快速判断方法 |
|--------|------------|
| 利润为真 | 经营现金流/净利润 ≥ 80%？有无大额应收/关联交易？ |
| 利润可持续 | 行业是否衰退？竞争格局是否恶化？核心产品是否有替代风险？ |
| 维持盈利无需大量资本 | 资本支出/净利润 ≤ 50%？是否重资产？ |

**Step 2：护城河快检**（巴菲特框架）

| 检验项 | 快速判断方法 |
|--------|------------|
| 商业模式 | 市场特许型/两者之间型/一般竞争型？ |
| 护城河 | 能否一句话说清？是什么类型？是否持久？ |
| 管理层 | 是否有明显的诚信/治理问题？ |

**Step 3：不为清单快检**（段永平框架）

| 检验项 | 快速判断方法 |
|--------|------------|
| 看得懂 | 能否用一段话说清靠什么赚钱？ |
| 非跟风 | 不是因为"大家都在买"或"概念热" |

### 检验结论分类

对每只候选股给出三档结论：

| 结论 | 标准 | 行动 |
|------|------|------|
| 🟢 **入池** | 三大前提通过 + 有可识别护城河 + 看得懂 | 进入股票池 |
| 🟡 **观察** | 大部分通过但有关键待确认项 | 入池但标注待确认问题 |
| 🔴 **排除** | 三大前提不通过 / 无护城河 / 看不懂 | 排除并说明理由 |

### 检验评分细则

将定性判断转化为可执行打分，避免主观模糊：

| 检验项 | 0分 | 1分 | 2分 |
|--------|-----|-----|-----|
| 利润为真 | 现金流/利润 < 80% 或大额应收 > 营收30% | 80%-99%，但有关联交易 | ≥ 100%，应收合理 |
| 利润可持续 | 行业衰退/核心产品有替代风险 | 行业平稳但竞争加剧 | 行业增长+格局稳定 |
| 维持无需大量资本 | 资本支出/利润 > 80% | 50%-80% | ≤ 50% |
| 商业模式 | 一般竞争型 | 两者之间型 | 市场特许型 |
| 护城河 | 说不清护城河 | 有护城河但持续性存疑 | 一句话说清+来源明确+持久 |
| 管理层 | 有诚信/治理污点 | 信息不足无法判断 | 无明显污点+口碑良好 |
| 看得懂 | 说不清怎么赚钱 | 大致理解但细节模糊 | 一段话说清盈利逻辑 |
| 非跟风 | 因概念热/他人买而关注 | — | 基于独立判断关注 |

**结论判定公式**：

```
Step 1 三项总分 ≥ 4  → 三大前提通过
Step 2 三项总分 ≥ 3  → 护城河可识别
Step 3 两项总分 ≥ 2  → 看得懂且非跟风

🟢 入池 = 三大前提通过 + 护城河可识别 + 看得懂且非跟风
🟡 观察 = 任一条件边界线（差1分通过）+ 无硬伤
🔴 排除 = 任一条件差2分以上 / 有硬伤（诚信污点/看不懂）
```

每只候选必须输出评分表 + 结论，不得跳过打分直接给结论。

## 检验结果

### 🟢 入池股票

|------|---------|-----------|---------|--------|

### 🟡 观察股票
| 公司 | 核心看点 | 待确认问题 | 需要什么信息 | 下一步 |
|------|---------|-----------|------------|--------|

## 失败模式处理

以下场景必须有明确的 if-then fallback，不可静默跳过或编造：

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| **搜索返回 0 只候选**（Phase 3） | 放宽 1 个量化条件阈值（如 ROE 15%→12%），重搜 | 向用户报告：该行业无符合条件公司，建议换个方向或手动提供候选 |
| **全部候选未通过量化条件**（Phase 3） | 列出条件最接近的 3-5 只（标注哪些条件未通过），询问用户是否放宽条件 | 向用户报告：当前条件过严，建议调整为宽松条件集重试 |
| **全部候选被排除**（Phase 4） | 检查排除理由是否过严；若有「观察」档的公司，重新审视是否降为入池 | 向用户报告：该方向暂无可入池标的，建议拓展行业范围或调低预期 |
| **用户无法确定投资偏好**（Phase 1） | 默认使用"长期复利"偏好，告知用户后续可切换 | 不适用——默认值总可用 |
| **用户提供的候选清单含无效代码**（Phase 1） | 逐个验证代码；无效的标出并询问是否用名称搜索 | 无效代码直接排除，仅对有效代码执行检验 |
| **财务数据多处无法获取**（Phase 3-4） | 标注「待验证」+ 用定性判断替代（如行业地位、品牌知名度）；诚实告知数据缺口 | 若超过半数的关键指标无法获取 → 该候选降为 🔴 排除 |

### 分支处理原则

- 每个"如果...则..."分支必须执行，不可跳过
- 兜底路径必须告知用户当前状态和建议
- 绝不静默失败（如搜索失败假装有结果）

## 反幻觉与证据规则

1. 财务数据必须标注来源（搜索结果/年报/数据平台）
2. 无法确认的数据标注"待验证"，不编造
3. 候选清单基于实际搜索结果构建，不凭记忆罗列
4. 诚实标注信息不足的领域——"没有找到XX数据"比编造数据好一万倍

## 工作流示例

### 示例 1：行业筛选

用户："帮我从A股白酒行业筛选值得研究的股票"

1. Phase 1：确认市场=A股、行业=白酒、偏好=长期复利
2. Phase 2：生成量化条件（ROE≥15%、毛利率≥40%、现金流/利润≥80%等）
3. Phase 3：搜索白酒上市公司 → 找到20只 → 用量化条件过滤 → 产出12只候选 → 用户确认
4. Phase 4：逐只用L1+L2逻辑快检 → 5只🟢入池、3只🟡观察、4只🔴排除
5. Phase 5：输出股票池清单，强制优先深研 Top 3

### 示例 2：用户提供候选清单

用户："帮我看看这8只港股互联网公司哪些值得研究：腾讯、阿里、美团、京东、百度、网易、快手、哔哩哔哩"

1. Phase 1：确认市场=港股、方向=互联网、8只候选
2. 跳过 Phase 2-3（已有候选）
3. Phase 4：逐只快检 → 腾讯🟢（强护城河）、阿里🟡（竞争格局变化待确认）、京东🟡（低毛利但现金流好）...哔哩哔哩🔴（利润为真存疑）
4. Phase 5：输出股票池清单
